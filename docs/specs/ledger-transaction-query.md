`m04.07-transaction-query.v1` reads complete committed synthetic journals from the unchanged immutable storage tables. `validateLedgerTransactionQueryCandidate(unknown)` validates without I/O. `createLedgerTransactionReader(explicitConnectionUrl)` exposes only `query(unknown)` and `close()`. It offers no financial write, approval or arbitrary SQL authority.

Every request requires exactly `contractVersion`, canonical `ledgerId`, `selection` and `cutoffs`. Cutoffs contain independent, inclusive `effectiveThrough` and `recordedThrough` UTC strings with milliseconds, years0001–9999. No implicit clocks, coercion, getters, hidden/inherited fields or unknown properties are accepted.

| Selection kind | Required fields besides kind | Meaning |
| --- | --- | --- |
| transaction_id | transactionId | Exact ledger and identity; absent/excluded identity gives an empty transactions array |
| source_reference | source with namespace and id; page | Exact ledger, source namespace AND reference; multiple journals may share a source reference |
| account_currency | accountId and USD/EUR/GBP currency; page | Journals containing at least one entry matching the supplied ledger/account/currency |

List `page` requires `size`, integer1–50, and `afterTransactionId`, canonical ID or explicit null. Identity mode refuses a page; mixed/partial filters refuse. Ordering and the exclusive continuation comparison use ascending transaction ID with PostgreSQL `COLLATE "C"`, independent of insertion/effective/recorded chronology. The bound need not identify an existing journal. A lookahead journal establishes continuation; the cursor is the last returned ID, never the omitted lookahead ID. Exact-size final pages and empty results have null continuation. The cursor is an explicit bound, not an authenticated opaque capability.

Account/currency filtering qualifies complete journals; it does not redact counteraccounts or other currency legs. These additional lines are required context. Selection isolation does not establish authorization, ownership or access control. No global Account registry, authenticated source lookup, idempotency/retry-key meaning or posting eligibility is provided.

Output is a frozen detached `LedgerTransactionQueryOutput`: echoed validated query, immutable `transactions`, `nextAfterTransactionId`, diagnostic `databaseSnapshot` and `statusScope: all_stored_headers`. Each record contains its complete validated `LedgerJournal`, its own referenced Account catalog, and exact bigint `entryCount`/`accountCount`. Existing journal validation supplies branded exact bigint amounts and per-currency totals. Bigint output needs an explicit serialization convention outside this API.

Each call opens an owned `REPEATABLE READ READ ONLY` transaction, selects distinct transaction IDs first with a parameterized limit, then independently aggregates every entry and snapshot. Account qualification uses EXISTS; hydration never filters entry lines. Independent row counts, exact referenced-account membership and existing Account/header/entry/journal validation reject incomplete balanced groups, malformed metadata and selection/order/cutoff mismatches. Every retrieved record including lookahead is checked; one malformed group rejects the entire page. Journal-local catalogs preserve differing historical metadata across journals. Stored names decode losslessly from dense UTF16 code units, including lone surrogates.

The reader commits before returning, rolls back/destroys failed sessions, exposes fixed sanitized errors with at most a canonical SQLSTATE, and never retries automatically. An explicit PostgreSQL URL must include host/positive port/database/user/password and no query/hash; ambient database variables are unused. The returned snapshot is diagnostic and not a durable cursor. Later page calls use later snapshots; subsequent commits, including backdated lower IDs, may appear or be missed behind the bound. `recordedAt` is supplied metadata, not a commit watermark. Journal count bounds do not bound journal byte size; no journal is truncated and no performance/SLA guarantee is claimed.

Executable learning example: store a synthetic balanced1250 debit/credit journal through the existing deterministic disposable test controls, then select its identity to obtain both entries and both Account snapshots. A wrong ledger gives no matching journal; a malformed identifier refuses before connection. Removing a balanced pair while the independent stored count remains larger rejects the full result. These assertions do not authenticate evidence or establish financial truth.
