# Balanced Posting Tests

M04.15 is test-only acceptance coverage of the existing M04.01–M04.14 contracts. It adds no runtime API, posting eligibility or state transition. The corpus, unit/property tests and mandatory PostgreSQL tests live only in `packages/ledger/test/`; no production source imports the corpus. Existing `postingImplemented:false`, every previous feature test/helper/specification and all THREE migrations remain unchanged.

The explicit synthetic corpus covers every ordered pair of the five accounting categories across USD/EUR/GBP and separately supplied pending and posted journal headers. Pending and posted inputs have distinct IDs; storage preserves each supplied status, and existing readers include all stored headers. An agent cannot promote a pending journal or infer posting authority. Test IDs start at11million, disjoint from the preserved9million migration fixtures and10million revenue fixtures.

Fixed decimal-string blueprints specify independent literal debit and credit totals:1250;1000+250=1250;9223372036854775807 twice=18446744073709551614;9007199254740993+7=9007199254741000. Per-line amounts are exact positive signed64 integers; aggregate totals are unbounded bigint. Tests compare each currency separately. Account-normal-positive balances follow each account's declared normal side and can be negative; their sum is not the double-entry conservation equation.

Each journal explicitly supplies Account snapshots, source namespace/id, two nonempty MoneyEvent references, two receipts/content hashes, ledger, currency, IDs, status and clocks. Pure validation must retain the declared metadata and exact amounts, freeze its checked output and leave the input unchanged. Re-materialization and deterministic entry/catalog/event/receipt permutations retain totals and semantic idempotency identity. Balanced duplication uses fresh entry IDs and doubles independent expected totals; it changes semantic payload identity and is not an exact retry.

Five existing role helpers are checked separately across the three currencies. Their single-currency context restrictions remain intact; a separate general M04.04 journal demonstrates conservation across all three currencies. No role, ownership, source, amount or accounting policy is inferred. The pure role helpers provide caller-declared consistency, not source authentication or general posting authority.

The eleventh sequential mandatory owned PostgreSQL17 suite composes unchanged store/query/balance/idempotency APIs. It checks exact journal/status/provenance/Account snapshot readback, bigint amounts and counts, account-normal arithmetic, both inclusive observation cutoffs, and repeated reads with byte-equivalent stored rows. Diagnostic databaseSnapshot tokens are not compared as stable persistent snapshots. A valid existing08 retry changes attempt IDs and declaration order only while retaining scope, clocks, status, line multiplicity and semantic metadata; one original receipt/history is recovered and no retry journal is stored.

Actual database evidence must be recorded in `docs/status/CURRENT_STATE.md` and the sole PR. The previous ten mandatory suites and their392 tests must remain intact; new15 counts are reported from actual execution, not quotas. Acceptance also requires THREE UP/DOWN/UP recovery, both populated migration upgrades with exact preservation/no backfill, exact six tables/ten functions and owned database/role/Compose cleanup. Pure tests alone do not prove database behavior. Local caches may be warm; local Docker/Postgres can be unavailable while the approved owned17 CI provides real acceptance.

Example: revenue credit1250 with asset debit1250 is balanced, and both account-normal-positive balances are+1250. Existing04 refuses a journal missing the counterline; the earlier invalid tests remain intact. Synthetic balance and caller declarations do not prove an economic occurrence, authenticity, earned revenue, policy correctness or settlement. M04.16 adversarial/rollback/concurrency and M04.17 cross-feature reversal corpora remain later gated work. No live money/evidence mutation, new DDL, approval or agent financial authority is introduced.

The coordinator runs `corepack pnpm --filter @causalledger/ledger exec vitest run test/balanced-posting.test.ts`, ledger/workspace checks, control-plane tests and the approved owned database route. The user need not run tests. Human review and merge follow independent overall QA and exact final-head CI.
